# =====================================================================
# Orden de las migraciones de VetLink. Lo lee scripts/migrate.sh.
#
# Esta lista es la fuente de verdad del esquema: mydb.sql es la base (V1) y
# cada archivo posterior la modifica. Hibernate solo VALIDA (ddl-auto=validate).
#
# Formato (separado por |):
#   id | archivo (relativo a database/) | tipo | marcador
#
#   id        identificador único y estable. NUNCA se cambia ni se reutiliza.
#   tipo      esquema = siempre se aplica.
#             demo    = solo con RUN_DEMO_SEED=true. Deben poder repetirse sin duplicar.
#   marcador  consulta que devuelve 1 si la migración YA está aplicada. Solo se usa una vez:
#             al adoptar una base creada antes de existir el historial (00-init.sh antiguo),
#             para registrar lo que ya tenía sin volver a ejecutarlo.
#
# Para agregar una migración nueva: crea database/migrations/V<N>_<descripcion>.sql y
# añade una línea AL FINAL. No edites archivos ya aplicados: el script avisa si su
# checksum cambió. V2, V3 y V4 no están porque mydb.sql ya los incluye.
# =====================================================================
